# PayPal AI Hackathon — verified requirements

Sources checked 2026-10-30:

- Overview: https://paypalaihackathon.devpost.com/
- Official Rules: https://paypalaihackathon.devpost.com/rules

## Core task

Build or update an application, agent, automation, payment experience, business
tool, or other product that **meaningfully uses both PayPal and AI**. There are
no prescribed tracks or problem statements. The project must:

- meaningfully integrate at least one PayPal technology, API, SDK, product, or
  developer capability;
- meaningfully incorporate AI into the experience or functionality;
- demonstrate a working prototype or proof of concept;
- be documented well enough for judges to understand and evaluate it;
- use the **free PayPal sandbox environment**;
- comply with the Official Rules.

Projects may be new or existing, but an existing project must make meaningful
progress during the hackathon. PayGuard Agent is a new build started for this
entry.

## Exact submission package

A complete submission needs:

1. A project satisfying the requirements above.
2. An English text description explaining features and functionality.
3. Access to a functional demo. Either:
   - complete setup and run instructions in the code repository so judges can
     build/run it themselves; or
   - a hosted demo URL.
   
   A mockup, static prototype, or non-functional demo does **not** qualify.
4. Identification of the AI tools/models/services used and how they were used.
5. A public code repository on GitHub, GitLab, or Bitbucket containing all
   source code, assets, and run instructions.
6. An open-source license file in the repository, detectable and visible at
   the top of the repository page / About section. This project includes MIT.
7. A public YouTube demonstration video:
   - under 3 minutes (judges are not required to watch beyond 3 minutes);
   - shows the project functioning on the device for which it was built;
   - linked on the submission form;
   - no third-party trademarks or copyrighted music/material without
     permission.
8. The project must remain available free of charge and without restriction
   for sponsor/administrator/judge testing through the end of judging.
9. Judges are not required to test the project and may judge from the text,
   images, and video alone, so the video and description must stand on their
   own.

Multiple submissions are allowed, but each must be unique and substantially
different. This plan prepares one submission.

## Judging

Stage One is pass/fail for theme fit and reasonable use of the featured
APIs/SDKs. Stage Two uses five **equally weighted** criteria:

1. **Technological Implementation** — thorough, skillful use of the PayPal
   Developer Platform and AI tool(s); genuine, working, non-trivial build.
2. **Design** — complete, coherent product experience rather than only a
   technical proof of concept.
3. **Potential Impact** — credible, specific case for solving a real problem
   for a real audience, with the demonstrated solution addressing it.
4. **Innovation/Idea** — creative and novel concept that differs from existing
   concepts.
5. **Presentation** — video clearly demonstrates the project end-to-end and
   communicates the problem, audience, and why it matters.

Ties are broken by comparing criteria in the order listed.
